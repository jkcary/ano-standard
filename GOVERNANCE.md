# Project governance

ANO is an early-stage open engineering specification and reference implementation. It is not an established industry standard or certification authority.

## Stewardship

The initial lead maintainer is [@jkcary](https://github.com/jkcary). The lead maintainer currently handles releases, merge decisions and scope. Contributors can participate through issues, pull requests, independent implementations and public design reviews. No committee or independent governing foundation is claimed.

## Decisions

- Routine fixes and documentation changes can be reviewed directly in a pull request.
- Normative requirements, public interfaces, compatibility changes and major dependencies need an RFC issue using the RFC template.
- An RFC must describe the problem, alternatives, compatibility, migration, security implications and executable acceptance criteria.
- Keep an RFC open for at least seven calendar days before accepting a non-urgent normative change. Record the decision and reasons publicly. Urgent vulnerability fixes may be handled privately first under SECURITY.md.
- Seek agreement through evidence and discussion. If agreement cannot be reached, the lead maintainer decides and records the rationale. Contributors may ask for reconsideration with new evidence.

## Maintainers and releases

Sustained contributions and reliable review can lead to a public maintainer nomination. Record scope and responsibilities before adding a maintainer. A contributor can step down at any time. Access changes are performed by the repository owner, not implied by a nomination.

Releases identify the implementation version, source revision, verification results and known limitations. Prereleases remain explicitly marked. No self-conformance result authorizes production deployment or grants certification rights.

The open core consists of the published specification, schemas, tests and reference implementation under LICENSE. This launch creates no paid service, support SLA or exclusive commercial rights. Any future commercial offering and its relationship to the open project should be documented openly.
