# AI Native Organism Engineering Specification v0.4

状态：`0.4.0` Reference Release  
兼容基线：`ANO 0.3.0 Public Draft`  
日期：2026-09-01

## 1. 目标与范围

v0.4 将 ANO 的可执行单机闭环扩展为可承载受控生产试点的参考内核。v0.3 的身份、目标、权限、行动、记忆、承诺、治理、自修改、模型跃迁和证据契约继续有效；v0.4 增加事务多租户、信封加密、密钥生命周期、外部签名身份、可移植迁移、备份恢复、持久租约、配额和 SLO。

核心架构不依赖某一模型、提示词或供应商。模型能力提升只能通过版本化 Capability Graph、候选编排、密封评测和治理发布进入运行时；确定性权限、租户、事务、审计、密钥、配额和回滚边界不得由模型绕过。更强模型应扩大可安全验证的候选空间、提高自治任务复杂度和学习速度，而不是迫使系统重写控制平面。

## 2. 生产运行不变量

| ID | 不变量 |
|---|---|
| `INV-025` | 每次持久化访问必须来自经验证且绑定唯一租户的会话；业务载荷中的租户字段不得决定存储作用域。 |
| `INV-026` | 状态、幂等键、版本、密钥和审计序号必须以租户为隔离边界。 |
| `INV-027` | 状态变更、幂等收据和审计事件必须在同一事务中提交或全部回滚。 |
| `INV-028` | 写入必须携带预期版本；并发写者不能用最后写入覆盖隐藏冲突。 |
| `INV-029` | 同一租户内幂等键只能绑定一个规范化请求；重放返回原事务，换内容复用必须拒绝。 |
| `INV-030` | 每个租户具有独立、连续、可外部锚定的审计链。 |
| `INV-031` | 迁移必须携带版本、墓碑、幂等历史、审计前缀、头摘要和包摘要，并在空目标原子导入。 |
| `INV-032` | 会话过期、绑定撤销、数据库错误、版本不明或证据损坏必须 fail closed。 |
| `INV-033` | 活动租户载荷必须使用随机数据密钥执行认证加密；数据库不得保存明文数据密钥。 |
| `INV-034` | 密文必须认证绑定 tenant、namespace、object ID、object version 和 key version，禁止跨作用域替换。 |
| `INV-035` | 租户数据密钥和 KMS 主密钥必须可独立轮换；旧密文在密钥有效时仍可读。 |
| `INV-036` | 加密删除必须清除全部目标租户的 wrapped DEK，并产生不可恢复收据，不得影响其他租户。 |
| `INV-037` | 外部身份必须验证 issuer、audience、key ID、签名和有效期；一次性 assertion 不得重放。 |
| `INV-038` | 跨存储迁移包必须在传输中认证加密；错误密钥、摘要、租户或非空目标必须拒绝。 |
| `INV-039` | 备份恢复必须在落盘前验证内容摘要，并在恢复后通过数据库完整性和审计头检查。 |
| `INV-040` | 排他租约必须持久化并分配单调 fencing token；失效持有者不得继续产生副作用。 |
| `INV-041` | 租户资源消耗必须原子、幂等、按窗口计量；拒绝的请求不得部分扣减。 |
| `INV-042` | SLO 观测和报告必须按租户、服务和时间窗隔离，且目标、样本数和结果可机器验证。 |
| `INV-043` | 适配器必须声明真实能力；单节点实现不得把事务性等同于多节点一致性。 |
| `INV-044` | 模型能力跃迁不得改变上述确定性不变量；模型输出只能作为候选输入，经既有验证与治理路径放大系统能力。 |

## 3. 租户访问与外部身份

受信路径为：外部 IdP 签名 assertion → 固定 issuer/audience/key 策略验证 → assertion 一次性消费 → Principal/Tenant 绑定 → 有时限 TenantSession → 存储层复验。调用者修改 principal、tenant、期限、audience 或签名后必须失败；存储 API 不接受覆盖会话租户的参数。

参考实现提供 Ed25519 assertion 验证器和 HMAC TenantSession。生产适配器可使用 OIDC、SPIFFE/mTLS、云 IAM 或等价身份，但必须保留相同的验证、重放和租户绑定语义。

## 4. 事务状态、幂等与审计

对象由 `(tenant_id, namespace, object_id)` 唯一标识。创建使用 `expected_version=0`；更新和删除引用当前版本；删除产生版本化墓碑。每次成功写入必须恰好生成一条审计事件，并与状态、规范请求摘要和幂等收据在一个数据库事务内提交。

读取状态或重放幂等收据时必须复验对应事件。审计验证必须从序号 1 检查前驱与记录摘要，并可用独立保存的头摘要发现尾部截断。

## 5. 信封加密与密钥生命周期

每个租户拥有版本化 AES-256-GCM 数据密钥；DEK 仅以 KMS 主密钥认证封装后的形式持久化。对象密文的 AAD 固定租户和对象版本作用域。轮换创建新活动 DEK，旧 DEK 转为 retired；KMS 主密钥轮换通过 rewrap 完成，不重加密业务载荷。

密码学删除把目标租户全部 wrapped DEK 置空并标记 destroyed。残留数据库页或备份中的密文不再可解密。生产系统仍需把 KMS/HSM 删除证明、备份保留期和法定留存纳入组织控制。

## 6. 迁移、适配器和恢复

`TenantStateStoreAdapter` 定义 put/delete/get/list/audit/export/capabilities 的最小可移植面。导出包含当前对象与墓碑、完整审计历史、幂等收据和自摘要；传输层使用独立 256-bit transfer key 认证加密。导入先验证全部状态—事件—收据绑定，只允许同租户空目标，并在单事务内重加密到目标 DEK 后提交。

SQLite 在线备份使用数据库 backup API，清单固定内容 SHA-256、大小和完整性结果。恢复要求新目标路径，恢复前后均验证。其他数据库适配器必须通过同一 `O-*` 行为测试；v0.4 参考发布不包含 PostgreSQL 驱动。

## 7. 多工作者协调、配额与 SLO

租约对每个资源持久保存 owner、lease ID、期限和单调 fencing token。获取新租约、过期接管、续租和释放必须串行化；所有受保护副作用的最终执行器必须检查 fencing token。

配额按 tenant、固定窗口和命名维度计量。operation ID 绑定规范请求摘要，使网络重试不重复扣费。SLO 观测按 tenant/service/time window 计算样本数、可用率和 p95 延迟；无样本不得报告达标。

## 8. v0.4 数据契约

`schemas/v0.4.0/catalog.json` 是唯一目录，覆盖：会话、外部身份、状态、事务、幂等、审计、KMS wrapped key、加密 envelope、轮换/销毁收据、迁移 envelope/收据、备份清单、租约、配额、SLO、适配器能力和机器验收报告。所有契约使用 JSON Schema Draft 2020-12 和独立的 `urn:ano:schema:0.4.0:*` 命名空间。

## 9. 一致性要求

| 测试组 | 强制语义 |
|---|---|
| `O-TEN/O-SES/O-TXN/O-CON/O-INT` | 租户隔离、会话期限、乐观事务、幂等和内部篡改检测。 |
| `O-PORT/O-E2E/O-SCH` | 审计导出、机器验收和 Schema 目录完整性。 |
| `O-ENC/O-KEY` | 静态密文、AAD 防替换、两层轮换和租户级密码学删除。 |
| `O-MIG/O-BAK/O-ADP` | 加密迁移、原子导入、恢复验证和能力诚实声明。 |
| `O-IDP/O-LEASE/O-QUOTA/O-SLO` | 外部身份、fencing、资源边界和可观测 SLO。 |
| `O-RC-001` | 一条命令完成生产内核端到端验收并生成 Schema 有效报告。 |

0.4 必须同时保持 v0.3 五档累计 Profile 兼容。发布报告必须绑定实现版本和完整源码摘要；报告与源码摘要不一致时不得声称符合。

## 10. 模型能力跃迁与自生长

ANO 的增长回路保持为：能力发现 → Capability Graph 差异 → 候选计划/技能/编排 → 隔离执行 → 密封评测 → 治理批准 → 灰度 → 证据验证 → 发布或回滚。模型越强，候选的跨度、组合深度和生成速度可提升；确定性门禁、权限上限、预算、租户边界和证据要求保持稳定。

因此 v0.4 的“自生长”不是运行中任意改写自身，而是可度量、可审计、可回滚的版本化演化。能力提升可以非线性，但生产权限不会随模型能力自动提升。

## 11. 完成边界与非主张

0.4.0 参考发布完成了单节点生产内核契约与可执行证据，不主张：

- SQLite 是 PostgreSQL、多节点共识、网络分区容错或跨地域高可用；
- 进程内参考 KMS 等价于云 KMS/HSM 或独立密钥托管；
- Ed25519 参考 IdP 等价于完整 OIDC、组织目录或硬件工作负载身份；
- SQLite 持久租约可跨不共享数据库的节点协调；
- 本地备份测试满足既定 RPO/RTO、灾备演练或监管认证；
- 自符合测试等价于安全审计、渗透测试、隐私、法律或行业认证；
- `ANO-S` 允许无人监管的生产自修改。

多节点数据库适配器、外部 KMS/IdP、跨区域故障注入和长期容量验证属于部署认证或后续版本，不属于本参考发布的虚假完成项。
